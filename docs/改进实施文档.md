## 2. 完整流程

### 寄件人

1. **首页**：点「寄一件」。
2. **拍照**（已有）：拍或选一张照片，上传。
3. **写话**：写一句要藏进去的话（≤ 60 字），署名可空。
4. **打包中**（新页 `/s/[job]`）：显示真实任务进度，**只显示真实状态**，不编假进度：
   - 「照片已收到」：上传完成。
   - 「正在变成 3D」：Lux3D 生成中，1～2 分钟。
   - 「排队拆零件」：同一账号的拆分是串行的，前面有任务时显示这一条。
   - 「正在拆零件」：拆分中，几分钟。
   - 「打包好了」：可以分享。
   - 失败时说清楚哪一步失败、可以重试。
   - 打包需要几分钟，要允许离开页面后回来继续看。任务 id 存 `localStorage`，首页显示「你有一件正在打包」。
5. **选藏在哪**：打包好后，3D 预览这件东西，默认把话藏在**最里层的零件**里。最里层由拆解分析算出，就是一开始被挡住方向最多的那块。寄件人可以点别的零件改，旁边实时显示「要拆 N 步才能拿到」。
6. **分享**：生成链接，复制按钮，加一张分享卡片，用寄件人的原照片做封面。

### 收件人

7. **打开链接**（`/p/[code]`）：先看到一个盖着的盒子，写「{署名}寄来一件东西」，点开后零件状态的物体出现。**换成 `LockProto`，不用 `GameScene`。**
8. **拆**：沿着畅通方向往外拉（原型已有）。
9. **取出纸条**：拆到藏话的那块，纸条抽出来（原型已有）。
10. **摊开**：两段式爆炸，最后一张全家福（原型已有）。
11. **写回信 + 装回去**（新增，第二段玩法，见 4.3）。
12. **寄回**：生成回寄链接。对方打开后，拆同一件东西，找到回信。

## 3. 技术方案

### 3.1 任务状态机：`/api/jobs`

- `POST /api/jobs`，参数 `{ imageUrl, sender, message }`：
  - 调用 `lux3d.imgTo3d.create({ img: imageUrl, version: 'G1', faceCount: 200000, outputFormat: ['glb'], enablePbr: true })`。
  - 参数参照 `scripts/lux3d/pipeline.mjs` 的 `imgTo3d` 分支，脚本用的是 `createFromFile`，这里有 URL 就用 `create`。
  - 返回 `{ jobId }`。
- `GET /api/jobs/[id]`：每次被轮询时推进状态机：
  1. 生成任务没完成：`tasks.retrieve` 查状态。
  2. 生成完成：记下生成产物 URL（2 小时失效）。如果当前账号没有正在跑的拆分，立刻 `partSplit.create({ glbUrl: 生成产物URL })`；否则记为「排队」。
  3. 拆分完成：**立即下载**拆分 GLB 到本地 `.data/models/<jobId>.glb`，因为 URL 2 小时失效。
  4. 返回 `{ stage, error?, modelUrl? }`。
- 状态存成 `.data/jobs/<jobId>.json`；用一个全局文件 `.data/split-lock.json` 记录当前正在跑的拆分。
  - `.data/` 加进 `.gitignore`。
  - 本地文件存储意味着部署要用常驻的 Node 服务器（自己的机器或云主机），**不能用 Vercel 无服务器函数**。提交时如需公网演示，用 `cloudflared` 隧道。
- `GET /api/models/[id]`：把 `.data/models/<id>.glb` 以 `model/gltf-binary` 流式返回，带缓存头。
- 拆分 GLB 约 16 MB，手机偏重。时间够就用 `@gltf-transform/functions` 做 `weld` 和 `simplify`；**不要上 Draco**，查看器对它的支持没验证过。

### 3.2 包裹链接

`lib/parcels.ts` 扩展成：

```ts
type Parcel = {
  m: string;        // 模型：预置物品 id（如 lamp）或任务 jobId
  s?: string;       // 署名
  n: string;        // 藏的那句话
  c: number;        // 藏在第几块（GLB 子节点顺序）
  r?: { s?: string; n: string; c: number }; // 回信（回寄时才有）
  t: number;
};
```

仍然不用数据库，整个包裹编码进链接。话最多 60 字，base64url 后长度可以接受。

### 3.3 预置物品（评委和首次访问都靠它）

- **先不要跑**：用户还没批准消耗 Lux3D 额度。等用户明确说开始再跑；一旦批准就尽早跑，因为拆分串行要排队。
- 用 `scripts/lux3d/pipeline.mjs` 再生成 **4～6 件结构多零件的硬朗物件**：
  - 候选：老式相机、手摇磨豆机、头戴耳机、机械闹钟、手电筒、订书机。
  - 优先用真实照片做图生 3D。
- 每件生成后，用 `node scripts/proto-test.mjs`（把 `/proto` 改成可传 `?item=<id>`）读出 `window.__PROTO__`：
  - `parts`：零件数。
  - `depth`：最少要拆几轮。
  - `initialFree`：每块零件一开始有几个畅通方向。
- **入选标准**：零件 ≥ 6，且 `depth` ≥ 4。不满足的不上首页（台灯是 7 件、深度 6，合格）。
- 给每件写 `public/items/<id>/meta.json` 的 `name` 和每块的人工 `label`。**看截图确认语义再写**，NOTES 里台灯的电源线就被包围盒误判过。

### 3.4 收件页

- `app/p/[code]/page.tsx`：解析包裹 → 模型地址（预置的 `/items/<id>/model.glb`，用户上传的 `/api/models/<jobId>`）→ 渲染 `LockProto`。
- `LockProto` 改造成接收 `coreIndex`：藏话的那块由链接指定，不再自动算。自动算的结果只作为寄件人那一步的默认值。
- 用户上传的物品没有人工零件名：摊开后的标签只显示编号，不显示名称，**不要编名字**。

## 4. 可玩性（用户明确说现在可玩性不够）

### 4.1 拆的手感（改 `LockProto`）

- 拉动有阻力曲线：前 0.08 跟手，之后越拉越沉（已有，系数调到拉起来有"卡扣松开"的瞬间）。
- 松脱瞬间做三件事：
  - 零件被弹出一小段（过冲 6%，回弹）。
  - 咔哒音，音高逐件升高（已有）。
  - 手机上 `navigator.vibrate(8)`。
- 被挡住时：
  - 零件闷响，原地抖一下。
  - 挡住它的零件描红边 0.9 秒（菲涅尔壳层，已有）。
  - **不要弹文字提示框**，最多在底部出现「卡住了」三个字。
- 每次往被挡的方向硬拽，记一次「硬拽」。纸条抽出来时显示「你硬拽了 N 次」，回信里也带上这个数。不做失败惩罚，只给一点小压力，也是寄回去时的谈资。

### 4.2 藏话的悬念

- 收件人不知道话藏在哪块。前面拆下的零件都只是零件，拆到藏话那块时，零件发暖光，纸条从缝里抽出来（纸条要有抽出动画，不是卡片直接出现）。
- 寄件人藏得越深，收件人拆得越久。寄件页显示「要拆 N 步才能拿到」，**这是寄件人一侧的玩法**。

### 4.3 装回去 = 寄回信（第二段玩法）

收件人写完回信，要把零件装回去才能寄回，这一段要和拆一样有手感：

- 零件从托盘里拖出来，原位显示**淡墨色的虚影轮廓**。
- 零件只能沿它当初被拆出来的方向插回去，拖到虚影附近会被吸附。
- 顺序约束：一块零件能装，当且仅当它的插入方向不会被**已经装好的零件**挡住。复用 `computeFreedom` 的射线检测，只对已装好的零件做。装错顺序就会卡住，和拆的时候一样闷响、描红边。
- 回信藏进哪块，由回信人选：默认是最后装进去的那块，也就是最里层。
- **之前用户的抱怨**：「2 那个地方看不清放的位置，怎么都对不上」。所以：
  - 吸附半径要大，零件中心距离 < 0.12 就吸附。
  - 当前可以装的零件，在托盘里轻微抬起。
  - 虚影一直显示，不需要猜位置。

### 4.4 视觉与动效

- **整站沿用首页视觉**：白纸 `#f6f5f1`，墨 `#111214`，3px 网点，宋体标题，Consolas 等宽数字，上下两条 1px 墨线。拆解页已经按这个改了，见 `app/globals.css` 的 `.lp-*`。
- 物体材质默认「墨色」：Lux3D 贴图乘深色，接近首页的黑色物体。右上角可以切原色和套色。
- 摊开用两段式（已有）：
  - 前 45%：从整体 45% 高度的中心放射出去，按高低分组偏置。
  - 45% 之后：零件码进互不重叠的格子，相机转到正面，按宽高两轴取大重新构图。
  - 75% 之后：浮出编号。
  - 参考 `E:\gitproject\_refs\ha\explosion-layout.ts`（human-atlas）和 `_refs\ct\car-exploded.html`（CTViewer）。
- 纸条：手写体（楷体），白边加细墨线，从零件缝里抽出（旋转 −4° 到 −1°，用回弹曲线 `cubic-bezier(.24,1.28,.4,1)`）。
- **不要**出现以下这些：
  - 紫色渐变、发光按钮、emoji。
  - 「Mock」「示意」「Demo」之类的标签。
  - 装饰性英文、步骤编号（「01 拍照」这类要去掉）。

### 4.5 摄像头手势（这次的主要亮点）

目标：像钢铁侠隔空拆装甲。用电脑摄像头，不戴任何设备，隔空把零件拉出来、把整件摊开。鼠标和触屏始终可用，手势是可选的增强。

已实现（待测）：
- `components/HandInput.tsx`：MediaPipe HandLandmarker，VIDEO 模式，最多 2 只手。wasm 在 `public/mediapipe/wasm/`，模型在 `public/mediapipe/hand_landmarker.task`，**都是本地文件，不要改成 CDN**（评委网络未必能访问谷歌）。
- 顶部「用手势」按钮打开，右下角是黑白镜像小窗，叠加关键点。
- 手势映射：

| 手势 | 判定 | 作用 |
|---|---|---|
| 单手捏合 | 拇指尖到食指尖距离 / 手掌大小 < 0.32 开始，> 0.46 结束（带回差） | 等同按住鼠标：捏住零件，往外拉 |
| 单手张开左右挥 | 四指都伸直，掌心横向位移 | 转视角（摊开状态下不转） |
| 双手张开拉开 / 合拢 | 两只手都张开，两掌心距离变化 | 摊开程度，等同滚轮；只在纸条取出后生效 |

- 光标：两个圆环跟随捏合点；捏合时缩小变黑，抓住零件时变红。
- 映射只用画面中间 70%，手不用伸到摄像头边缘。平滑按速度自适应：慢移稳，快移跟手。

要做：
1. 跑通测试（第 1 节）。
2. **用户实测**：在真实摄像头前拆完整件台灯，记录哪里难用。重点看：捏合误触发、抓住后手抖导致零件回弹、光标抖动、左右手编号跳变。这些阈值都在 `HandInput.tsx` 顶部常量里，按实测调，不要改成别的手势体系。
3. 抓住零件时调一次 `navigator.vibrate` 没意义（电脑），改为在光标上做一圈收紧动画即可。
4. 零件被拉出瞬间，光标处出一个小的墨点扩散，和咔哒声同步。
5. 首页加一句入口：「也可以用手拆，打开摄像头就行」，放在「试一件」旁边，不要单独做一屏介绍。
6. 摄像头画面只在本机处理，不上传。在说明入口写明这一点。
7. 没有摄像头 / 拒绝权限时，小窗显示原因，点 × 关掉，回到鼠标，不报错。

不要做：语音控制（用户暂不做）；超过上面三种的手势；手势教学弹窗。

### 4.6 文案规则

- 短，具体，像人说的话。按钮用动词：「寄出去」「拆开」「全部摊开」「装回去」「寄回给小周」。
- 不教人怎么玩：
  - 只在第一次出现一句「按住零件，往外拉」，拆下第一块后消失。
  - 不写「恭喜你」「太棒了」「探索」「开启旅程」。
- 等待页只说真实发生的事，见 2 节第 4 步。

## 6. 验收

每条都要有截图或命令输出，不能只说"已完成"：

1. 用一张**新拍的真实照片**，从首页走到分享链接，全程不碰命令行，截图存 `.tmp/e2e/`。
2. 在另一个浏览器（无痕）打开链接，拆到纸条，看到的话和寄件时写的一字不差。
3. 写回信、装回去、拿到回寄链接；用第一个浏览器打开，拆到回信。
4. 打包中页面刷新、关掉再打开，状态都能接上。
5. Lux3D 任务失败时（可以传一张纯色图触发），页面说清楚失败在哪一步，有重试按钮。
6. 手机（iOS Safari、Android Chrome）能拆、能拖、能装回。
7. `npx tsc --noEmit` 和 `npm run build` 通过。
8. 手势：真实摄像头下，只用手拆完台灯、取出纸条、双手摊开再合拢。录一段 20 秒屏幕视频存 `.tmp/e2e/hands.mp4`，这段也是演示视频的开场。
9. 拒绝摄像头权限后，鼠标仍能完整玩完。
8. 预置物品每件的 `parts` 和 `depth` 记录到 `NOTES.md`。
