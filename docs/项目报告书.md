## 一、这是什么

一盏旧台灯，拆成七块，装进一条链接里寄出去。

寄件人没写卡片。他拍了一张照片，让 Aholo Lux3D 把它变成一个带材质的模型，再拆成零件；把那句话压在最后一块底下，把整件交给收件人。

你点开链接，看见的是一件墨色的、没有名字的东西：看得出是"一件东西"，说不准是什么。每一块都能往外拉。拉下一块，它就当场恢复原色；拉错方向，那张信的纸边就被撕掉一截。一直拆到最后一块，纸条才抽出来。

那句话可能只是"灯我给你修好了"，也可能是三年没说的话。它非得被动手拆开一次，才算真的送到。

一句话：**把一句话藏在一样东西的零件里，收件人得亲手把它拆开才读得到。**

## 二、它有什么用

台灯只是这一件的样本，真正被做出来的是一个**能装话的容器**：任何一件能被拍下来的东西，都能走同一条链路，变成一封需要动手才拆得开的信。

| 用得上的地方 | 谁在用 | 为什么非这样不可 |
|---|---|---|
| 旧物寄情 | 异地恋人、家人、毕业分开的朋友 | 东西本身就是那段时间的证据；话压在零件里，对方得一件件拼回形状才读到，读到的同时把这段记忆也拼了一遍 |
| 二手转赠 | 闲鱼、旧物交换、朋友之间的"传下去" | 转赠最缺的是一段来历。附一条链接，新主人拆开时会知道它哪块最旧、陪了多久，旧物因此不是"处理掉"，而是"交出去" |
| 品牌与展览 | 做礼盒、做快闪、做展陈的团队 | 同一个模型可以反复寄给不同的人，每次只换那句话；开箱从"撕一层包装"变成"拆一件东西"，记忆点落在动作上 |
| 从屏幕到桌面 | 想把这件东西真的留下的人 | 摊开后导出 STL，七块直接进切片软件；屏幕上的那封信可以变成摆在原来那盏旁边的实物 |

为什么值得花力气做"拆"：一句话说出来只要一秒，但要让人真的记住，得让它有代价。拆错会撕纸、拆对才恢复原色、最后一块才见字——这三十秒的代价，是这封信的分量。

而且这套东西是可复用的资产：模型负责形状，包裹码只带那句话和署名，回信不重新生成、不消耗额度。同一盏灯寄给十个人，是十封信；同一个模型导成 STL，是十件能打印的实物。

## 五、技术怎么实现的

### 5.1 一件东西两次 Lux3D 任务

现在的寄件链路是两步：

1. `imgTo3d.create({ imageUrl, faceCount: 200000, glb, enablePbr, aiPredictSize })` —— 照片出带材质的形状。
2. `partSplit.create({ glbUrl })` —— 按结构拆成独立零件，回一个拆分后的 GLB。

产物落到 `public/items/<id>/`，再跑一次材质回压，数 GLB 节点写进 `meta.json`，任务号与 URL 写进 `pipeline.json`，页面上原样展示。首页那三件示例件走的是同两步；早期展厅里那盏用文字描述生成的台灯（`6974188` / `6974827`）走的是 `textTo3d`，批次更早，数字留在旧记录里。

### 5.2 为什么拆分产物这么好用

七个 mesh 各自独立，坐标已经烘焙到世界系。拆一块不需要重算矩阵：给每块一个方向向量，让它沿自身相对整体的径向飞出去即可。方向按高度分带（上部往上、贴地往两侧），避免七块挤成一团。

### 5.3 玩法：难度不在"拆"，在"顺序"

拆装本身没有难度，所以难度被放在两处：

- **脱开方向可见，能不能动不可见**。鼠标移到零件上、或开始拖时，从零件上画一支白箭，指向它脱开的方向。但被别的零件压着的件同样有箭头——箭头只说"它往哪边走"，不说"它现在能不能走"。要试。
- **顺序有代价**。拽错方向记一次撬痕；硬拉被压住的件也记一次。被压的件前两次只抖一下、闷响，第三次才点名"先拆灯罩"。撬痕会撕掉纸条：每道撬痕吃掉纸的一截，尾句连同纸边一起没了，拆完还可以"重新拆一次"。
- **拆开一块，才认出一块**。开场整件是墨色剪影，看得出是「一件东西」，看不出是台灯还是别的；每块被拉下来时当场恢复原色，形状是一块块被你认出来的。
- **拆完有答案**。纸条上多一行「最旧的一块：<零件名>」，摊开后的货架标签同样标出这一块。拆的过程因此不只是拆，是在读一个人和一件东西的相处时间。
- **拆完有账**。纸条底部一行结算：「拆了 7 块 · 硬拽 0 次 · 用了 9 秒」，并存进本机；同一件再拆一次会写「比上次快 12 秒」或「比上次少硬拽 1 次」。重拆因此有理由，不是重复劳动。

### 5.4 四档显示

- 墨色：整体压成印刷品单色。
- 原色：还原材质，让评委看清模型细节。
- 套色：七块各乘一个孔版油墨色，像丝网分色稿。
- 线框：退成接近白模，只留 30° 折角的结构线。阈值是算出来的——全画三角网就是一团噪点，只留折角才读成制图线。

四档切换真实复原贴图、粗糙度、金属度，切回墨色不留白模残留。

### 5.5 手势

MediaPipe HandLandmarker 本地跑，模型与 wasm 都在 `public/mediapipe`，画面不出本机。

- 捏合判定：食指指尖与拇指指尖距离对掌心尺度的比值，`<0.40` 抓住、`>0.56` 且明显张开手掌持续 300ms 才松手。
- 捏住之后每帧补抓：手先捏、再挪到零件上也能抓住，不必先松手重捏。
- 抓取吸附 110px：指尖在 640×480 里只有十几个像素，细杆、电源线靠点准是点不中的。
- 单手横扫转视角，抓着东西时禁用，避免挥手把零件甩掉；双手拉开控制摊开程度。
- 张开手掌停住 0.8 秒，整件散开；握拳停住 0.6 秒，又拼回去。握拳时指尖本来就贴着拇指，会被当成捏合去误抓零件——所以握拳判定先算、再压制捏合，顺序在代码里是硬约束。
- 真机验收：两次真摄像头测试，状态轨迹出现「捏住了 → 抓住了，往外拉」，实测拉掉一块（已拆 1/7），抓着时转视角误触帧数为 0。

### 5.6 回信为什么不重新生成

回信只是换一句话和署名，模型一个字都不用动。`/api/reply` 把原包裹码里的物件 id、照片、收件人署名与新句子重组成新码，跳到新的装盒页。这一步不调 Lux3D，不消耗积分，收件人回一句的成本是零。

### 5.7 拆完的那件，真能打出来

拆件产物本来就是分割好的实体几何，所以"能不能打印"不需要另做一版模型，只需要把零件交出去：

- 摊开底栏一枚「下载 STL 去打印」，把每一块按自身几何中心归零，导成一个独立 STL（二进制），文件名带编号和零件名，如 `03-灯罩.stl`。
- 台灯那件的七个文件实测共 13.2MB：灯泡 1.85MB、灯臂 0.83MB、灯罩 3.88MB、灯头接头 0.58MB、灯杆 0.94MB、底座 3.13MB、电源线 1.72MB。
- 因为每块都归零并独立成文件，切片软件里不用再手动拆分摆盘；零件之间的装配关系由顺序与标签说明，和拆件时看到的顺序一致。
- 细杆、电源线这类细长件在真实打印里需要加支撑，这一层交给切片软件，页面只负责把可用几何交出去。

## 七、已知限制与下一步

1. **两个入口：一个给境内，一个给生成**。`https://www.modelscope.cn/studios/HpIahtcthocw/wumingjian` 是魔搭创空间的 Docker 部署，境内直连，打开就是收件页，七块都能拆、能回信、能导出 STL；`https://chai-le-ji-gei-ni.vercel.app` 是 Vercel 那份（含现场生成），但 `*.vercel.app` 在国内被解析污染、边缘拒绝 TLS，境内评委请用魔搭入口。现场生成受无状态函数 60 秒上限约束，线上只做轮询，不做同步等待。
2. **命名还得手工补**。台灯、收音机、台扇这三件写了零件名；新跑出来的件 `meta.parts` 仍是空的，标签回落成"第 N 块"。命名还没接进生成流程。
3. **现场生成要等**。单件 5–10 分钟建模、1–2 分钟拆件，页面上直说"这件事要几分钟，不用守着"；线上函数受 60 秒限制，只能靠前端轮询任务状态。
4. **手势刚达可用**。阈值与吸附为真机手调，不同光线、不同手掌大小仍会有偏差；张手／握拳只在合成 landmark 上验过，真正的摄像头面前还没人眼看过一遍。
5. **摊开时零件是放射散开**。标签跟着每块走，但摆位偶尔互压，属观感问题，不影响判定。
6. **打印还需要切片软件**。页面给出的是零件几何，支撑、摆放、材料参数在切片软件里定；细长件必须加支撑。

下一步：把零件命名接进生成流程；补一张分享卡，让链接转发出去不是白块；把同一套链路接成可批量寄的寄件单。
