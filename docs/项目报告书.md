## 一、作品是什么

**拆了寄给你 · 无名件：一封要动手才拆得开的信。**

寄件人拍一张照片，Aholo Lux3D 把那件东西变成带材质的 3D 模型，partSplit 按结构拆成零件；那句话被压在最后一块底下，整件东西装进一条链接发出去。收件人打开链接，先看到的是一件墨色剪影——看得出是"一件东西"，认不出具体是什么；得一块一块把零件拉下来，最后一块底下才抽出那张纸条。

| 谁 | 做什么 | 得到什么 |
|---|---|---|
| 寄的人 | 上传一张照片，写一句话、署名 | 一条链接；模型现场生成，话压在最后一块底下 |
| 收的人 | 打开链接，把零件逐个拽出来 | 每拉下一块当场恢复原色；最后一块底下抽出纸条 |
| 拆完之后 | 导出 STL，或回一句话 | 零件进切片软件打印成实物；或对方收到一条新链接 |

四个页面是同一次寄件的四步：寄件台（选照片、写话、生成、装箱）→ 收件拆件 → 回信 → 装盒清单。台灯是这一件的样品，任何能被拍下来的东西都能走同一条链路。

## 二、从想法到成品：三次推翻

这个作品不是一次成型的，下面三次否决都真实发生过，也决定了最后的形态。

| 最初的想法 | 为什么被否 | 改成什么 |
|---|---|---|
| 做一件"能拆的台灯"展品 | 只能适配这一件东西，换一件就得重做一套；评委看完只会记得"一盏灯" | 把链路做成通用的：任意照片进，同一套拆件、回信、导出 |
| 拆完让收件人答题猜这是什么 | 剪影一出来答案几乎写在脸上，题目变成画蛇添足 | 去掉答题，把"认出这是什么"交给拆的过程本身 |
| 把纸条直接铺在画面中央 | 纸条挡住主体，第一眼看不到那件东西 | 纸条压到最里面那块底下，拆到那儿才抽出来 |

定稿的判断只有一句：**拆是动作，话才是内容。** 所以后面补的三件事都围绕"话怎么送到"——寄件台能写话、回信能再寄一次、摊开后能把零件打成实物。

## 三、制作过程：一件东西怎么长出来

这一件用的就是比赛期间真跑过的链路，每一步都有产物和体积可查：

| 阶段 | 做了什么 | 产物 | 量级 |
|---|---|---|---|
| ① 上传原图 | 选一张白底台灯图，在浏览器里压到 1600 宽再上传，原图不出本机 | 源图 | 39KB |
| ② 图生 3D | imgTo3D 出带材质的完整形状（哑光塑料、灯罩内侧有内壁） | 带材质 GLB | 任务 8235025，20 万面，15.5MB |
| ③ 结构拆件 | partSplit 按结构拆成 7 个独立零件，几何烘焙到世界坐标 | 拆分 GLB | 任务 8235303，约 98 秒 |
| ④ 材质回压 | 拆分产物默认偏亮，在雾白底上像塑料；统一压到 metallic 0.12 / roughness 0.5 | 上线用 GLB | 7 个 mesh |
| ⑤ 上线成件 | 墨色剪影开场 → 逐块拉下恢复原色 → 最后一块抽纸条 → 摊开贴标签 → 导出 STL | 收件页 | 拆 7 块、硬拽 0 次、37 秒 |

[[ITER]]

**可对比的两处改动：**

- 材质：同一件模型，回压前在雾白底上发亮、像塑料；回压后压成墨色金属，灯罩内侧的转折才读得出来。
- 显示：同一件东西有四档——墨色（开场认不出）、原色（看清材质）、套色（七块各一色，像丝网分色稿）、线框（退成白模只留折角线）。四档切换真实复原贴图与金属度。

同一套链路还跑过五件不同形状的东西，用来证明它不是为一盏灯定制的：老收音机（7 块）、台扇（5 块）、拨盘电话（3 块）、双铃闹钟（7 块），以及现场再跑的一件（7 块）。六件的拆件页都能打开、都能拆、都能装回去、都能导出 STL，首页门口就摆着这些件。

## 四、玩起来是什么感觉

关键效果：

| 效果 | 数字 |
|---|---|
| 生成一件（照片 → 带材质模型） | 约 5–6 分钟，产物 15.5MB |
| 拆成零件 | 约 98 秒，7 个独立 mesh，坐标已烘焙 |
| 完整体验 | 打开链接即拆，7 块，硬拽 0 次，37 秒读到最后一块 |
| 打印导出 | 7 个 STL，共 13.2MB，每块独立归零 |
| 手势 | 真机拉掉一块、抓着零件转视角误触 0 帧 |

难度不在"拆"，在"顺序"：箭头只说明零件往哪边走，不说它现在能不能动——被别的块压着的件同样有箭头，得试。拽错方向记一次撬痕，撬痕会撕掉纸条的一截，尾句跟着纸边一起没了；被压住的件前两次只抖一下、闷响，第三次才告诉你先拆哪块。拆完还有账：纸条底部写"拆了 7 块、硬拽 0 次、用了 37 秒"，同一件再拆一次会写"比上次少硬拽 1 次"。

## 五、技术要点

1. **一件东西两次 Lux3D 任务。** imgTo3D 出带材质形状，partSplit 按结构拆零件；两个任务号与产物地址都在页面上可查。
2. **拆分产物自带坐标。** 七个 mesh 各自独立、已烘焙到世界系，拆一块只需沿自身径向给一个方向，不必重算矩阵。
3. **手势在本地跑。** MediaPipe HandLandmarker 的模型与 wasm 都在仓库里，画面不出本机；捏合判定用指尖/掌心比例，抓取带 110px 吸附，握拳判定先于捏合，避免握拳被当成抓取。
4. **回信不重新生成。** 回信只换那句话与署名，模型一个字不动，收件人回一句的成本是零。
5. **拆完能打印。** 零件本身就是分割好的实体几何，导出时每块按自身几何中心归零、独立成 STL，切片软件打开就能摆盘。

## 六、为什么值得体验

- **对收件人：** 收到的是一个需要动手三十秒的东西。话不是弹出来的，是拆出来的——三十秒的代价，就是这句话的分量。
- **对寄件人：** 照片进、链接出，不用建模、不用会 3D 软件；一件旧物的形状和一句话一起寄走。
- **对做礼盒/展陈的人：** 同一个模型可以反复寄给不同人，每次只换那句话；回信不消耗额度。
- **对想把东西留下的人：** 摊开后导出 STL，屏幕上的那封信可以变成摆在原来那件旁边的实物。

## 七、边界与下一步

1. **两个入口分工不同。** Vercel 那份含现场生成，但 `*.vercel.app` 在境内解析被污染，我本机实测打不开；魔搭创空间那份境内直连，默认首页是三件示例的收件页，寄件台在 `/live`。魔搭运行时关闭了在线生成，只展示已生成的件与全部拆件、回信、STL 导出。
2. **命名还得手工补。** 三件示例写了零件名；新生成的件标签回落成"第 N 块"，命名还没接进生成流程。
3. **现场生成要等。** 单件建模 5–10 分钟、拆件 1–2 分钟，页面直说"这件事要几分钟"；线上函数受 60 秒上限约束，只能靠前端轮询任务状态。
4. **手势刚达可用。** 阈值与吸附为真机手调，不同光线、手掌大小仍有偏差；张手／握拳只在合成 landmark 上验过。
5. **打印还需要切片软件。** 页面给出的是零件几何，支撑、摆放、材料参数在切片软件里定；细杆、电源线必须加支撑。

下一步：把零件命名接进生成流程；补分享卡，让链接转发出去不是白块；把同一套链路接成可批量寄的寄件单。
