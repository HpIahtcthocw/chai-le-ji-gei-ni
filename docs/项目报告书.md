## 一、这是什么

一件东西被拆成七块寄给你。你只知道寄件人是谁，不知道寄来的是什么。一块一块往外拉，每拉出一块，形状越来越清楚，最后一块里夹着寄件人写的那句话。

一句话：**把一句话藏在一样东西的零件里，收件人得亲手把它拆开才读得到。**

## 二、为什么值得做

寄礼物这件事，难的不是买东西，是写那句话。写在卡片上太轻，发在聊天框里太随便。这个项目试的是另一种载体：把话藏进一个具体的物件里，让它必须被"动手"才能兑现——拆的过程本身成了那封信的信封。

对收件人来说，这一分钟里发生的事是：认不出 → 猜 → 认出 → 读到最后一块里的那句话。三步情绪，全部由一个真实的 3D 模型承担。

## 三、一次寄件的完整流程

设计上共十二步，当前真实执行情况如下：

| 环节 | 状态 | 说明 |
|---|---|---|
| 首页交代这是什么 | 已做 | 首屏滚动驱动，往下滚看它怎么拆 |
| 上传一张照片、写一句话、署名 | 已做 | `/send`，照片存进包裹编码 |
| 出链接与二维码 | 已做 | `/api/parcel` 生成 base64url 编码，7 段可复制 |
| 收件页拆件 | 已做 | `/p/<code>`，真实 Lux3D 拆分产物，七块逐个拉出 |
| 摊到货架、看零件标签 | 已做 | 七块散开落位，编号 + 名称 + 引线标注 |
| 最后一块翻出纸条 | 已做 | 纸条文本来自 `meta.json` 的 story 字段 |
| 换显示档（墨色／原色／套色／线框） | 已做 | 四档实时切材质，可来回切 |
| 摄像手势操作 | 已做（未真人验收） | 捏合抓取、挥手转视角、双手摊开 |
| 上传照片 → 真实生成自己的物品 | 已做 | POST /api/jobs 起真任务：img-to-3D 出形状 → 零件拆分 → 落盘成自己的物品；2026 年 11 月 17 日实测一次（job jmwkpt3mu8o6hb，7 块，15.5MB） |
| 生成过程进度页 | **未做** | 文档里的 `/api/jobs` 状态机、`/s/[job]` 进度页均未开工 |
| 寄件人选「话藏在第几块」 | **未做** | 编码里没有该字段，现在固定藏在最后一块 |
| 收件人回信 + 装回去 + 回寄 | **未做** | 无回信入口 |

表里还没做的两行是当前最实的短板：那句话目前固定藏在最后一块，收件人也没有回信的入口。生成这一步是真跑通的，不是示意。

## 四、技术方案

### 4.1 模型从哪来

演示件用群核 Lux3D 的文本生 3D 做，真寄件走图片生 3D，两条路都是同一个 SDK。演示件：

- 文本生模型（task 6974188）：提示词锁定"圆形配重底座、细金属灯杆、可调节灯臂、圆锥形灯罩、结构清晰部件分明"，一次出 `source.glb`。
- 零件拆分（task 6974827）：`PartSplitRequest { glbUrl }`，产出 16.2MB 的 `model.glb`，七个独立 Mesh，几何已烘焙到世界坐标。
- 多格式导出（task 6977071）：`printable.stl`，12.95MB，271,602 面，页脚写的"可导出 STL"指的就是它。

一件物品三次任务。这个数字我在页面上没有藏，页脚直接写"可导出 STL"，因为它是这个项目真实的技术成本。

### 4.2 为什么拆分产物这么好用

七个 Mesh 各自独立，且坐标已经在世界系里——这意味着拆开一块不需要重算矩阵：给每块一个方向向量，让它沿着自己相对整体的径向飞出去即可。方向不是随机：按高度分带（上部往上、贴地往两侧），避免七块挤成一团。

### 4.3 材质为什么手动调

拆分出来的 GLB 材质偏亮，金属度太高，放在雾白底上像塑料。用脚本把 metallic 压到 0.12、roughness 提到 0.5，才变成可以放在纸面上的"哑光金属"。原文件备份在 `.tmp/model-backup.glb`，随时可回退。

### 4.4 四档显示

- 墨色：整体颜色乘一层深墨，压成印刷品的单色感。
- 原色：还原真实材质，用来让评委看清模型细节。
- 套色：七块各乘一个孔版油墨色，像丝网印刷的分色稿。
- 线框：物件退成接近纯白的白模，只保留 30° 折角的结构线。阈值 30° 是算出来的——27 万面全画成三角网就是一团噪点，只留折角才读成制图线。

四档切换会真实复原：贴图、粗糙度、金属度都单独存了一份，切回墨色不会有残留的白模。

### 4.5 手势

用 MediaPipe HandLandmarker 在本地跑，模型与 wasm 都放在 `public/mediapipe`，不上传任何画面。

- 捏合：食指指尖与拇指指尖距离对掌心尺度的比值，低于 0.32 抓住、高于 0.46 松开，双阈值避免抖动。
- 单手张开：按掌心横向位移转视角。
- 双手张开：按两手间距变化缩放摊开程度。
- 手感上做了速度自适应平滑（快移跟手、慢移稳），冷却文案只在动作变化时更新一次，避免每帧触发 React 重渲染和 three.js 抢主线程。

## 五、视觉决策

界面按 Aholo 官网主视觉的语言做：雾白冷灰渐变底、1px 细线、深色胶囊控件、电光蓝点缀。零件标注用细引线加箭头，署名处写真实的"渲染与生成"来源，因为这是加分项里最容易被验证的一条——技术栈不是写在报告里，是写在你打开页面的第一眼。

文字上坚持去装饰：没有英文小标签，没有 01/02/03 编号，没有"探索更多"。替换的是一句能听懂的话："按住一块，往外拉"。

## 七、已知限制（如实写明）

1. 没有部署。当前只能在本地 `npm run dev -p 3100` 打开，评委无法直接访问。
2. 上传照片不会真的生成物品。所有包裹播放的都是同一台预置台灯，页面上也没有标注"示例"，这一点在正式提交前必须改成真实链路，或者明确标注为预置。
3. 手势没有真人验收。摄像头管线、抓取、转视角、双手摊开的代码路径都跑通了，但自动化测试用的是假摄像头，画面里没有真手，骨架和捏合的实际手感需要人工确认一遍。
4. 只有一个物品。第二、第三件（比如椅子、收音机）没有做，物品越多越能证明这套流程是通用的。
5. 项目名"无名件"用户仍觉得太直白，备选名未定。
6. 生成进度页、回信与回寄、寄件人选"话藏在第几块"三处未开工。

## 八、90 秒 Demo 脚本

| 时间 | 画面 | 要做的事 |
|---|---|---|
| 0–6s | 首页静止 | 不动，让"无名件"三个字和台灯占满屏幕，右下角"它每天最后一个关掉自己。"先给一点悬念 |
| 6–14s | 首页滚动 | 滚到中段，灯亮起来，七块开始沿径向飞出，镜头拉远 |
| 14–20s | 滚到底 | 七块散到最大，右侧清单带引线逐条亮起 |
| 20–26s | 点"寄一件" | 进 `/send`，选一张照片，写一句话，署名"小周"，出链接 |
| 26–30s | 链接与二维码 | 复制链接，切到收件页 |
| 30–52s | 收件页拆件 | 七块逐个按住往外拉，第 4 块拉出时停一下，让形状开始可疑；最后一块翻出纸条，镜头停 3 秒 |
| 52–58s | 摊到货架 | 点"全部摊开"，七块散开落位，编号与名称的引线出现 |
| 58–64s | 四档显示 | 依次点墨色、原色、套色、线框，每个停 1 秒，线框那档停 2 秒 |
| 64–78s | 手势 | 打开"用手势"，一手指尖捏合抓住灯罩往外拉，再张开手掌左右挥转视角，最后双手拉开让零件摊平 |
| 78–90s | 收尾 | 回到整件，镜头缓慢绕半圈，字幕："一件东西七块，一句话藏一块。" |

录制要求：1440×900、无浏览器边框、鼠标不出现（手势段除外），全程无加载转圈。

## 九、复现

```bash
npm install
npm run dev -- -p 3100
# 收件页：http://localhost:3100/p/<code>
# 寄件页：http://localhost:3100/send
# 原型页：http://localhost:3100/proto
```

验证脚本：

- `node scripts/flow-test.mjs`：首页 → 上传 → 出码 → 收件页全链路断言
- `node scripts/proto-test.mjs`：拆七块、纸条、摊开、手势开关
- `node scripts/finish-shot.mjs`：四档显示截图
- `node scripts/hand-shot.mjs`：手势面板截图

真实生成（消耗积分，需确认后执行）：

```bash
node --env-file=.env.local scripts/lux3d/pipeline.mjs --id <物品> --prompt "..."
```
