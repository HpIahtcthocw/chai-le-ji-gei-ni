# 无名件 · 项目报告书

参赛：群核 Aholo 3D AI Hackathon
代码：`chai-le-ji-gei-ni`（Next.js + three.js + Aholo Lux3D）
本地运行：`npm run dev -- -p 3100`

---

## 一、这是什么

拍一张照，那件东西会被拆成零件寄给你。你只知道是谁寄的，不知道寄来的是什么。一块一块往外拉，每拉出一块，形状越来越清楚，最后一块里夹着寄件人写的那句话。

一句话：**把一句话藏在一样东西的零件里，收件人得亲手把它拆开才读得到。**

## 二、为什么值得做

寄礼物难的不是买东西，是写那句话。写在卡片上太轻，发在聊天框里太随便。这里换一种载体：把话藏进一个具体的物件，让它必须被"动手"才能兑现，拆的过程本身就成了那封信的信封。

收件人在一分钟里经历：认不出 → 逐个零件拼出形状 → 认出 → 读到最后一块里的那句话。三步情绪全部由一个真实的 3D 模型承担，不是一段视频，不是一张图。

## 三、一次寄件的完整流程（全部已实现）

| 环节 | 页面 | 现状 |
|---|---|---|
| 拍一张照、写一句话、署名 | `/send` | 前端把照片压到最长边 2048 的 JPEG，POST `/api/upload` 落成远程 URL |
| 起真实生成任务 | `POST /api/jobs` | 写 job 记录，后台 worker 起 Lux3D 两条任务 |
| 生成过程可见 | `/job/<id>` | 六步：「照片到了 / 认出了它 / 正在长 / 拆成零件 / 装进盒子 / 等人打开」，附 Lux3D 任务号与耗时 |
| 装盒清单 | `/s/<码>` | 按真实零件数排 01…NN，右半屏放原照片，链接可复制 |
| 收件人拆件 | `/p/<码>` | 七个独立 mesh 逐个拽出、摊开、贴标签、四档材质 |
| 回一句话寄回去 | `/r/<码>` | 回信写回，生成新包裹码，跳到新的装盒页；不重新生成模型，不消耗额度 |
| 摊开后还能往回走 | `/p/<码>` | 摊开状态的底栏有「再看纸条 / 回他一句 / 装回去 / 门口」，读完了还能重读、还能回信 |

闭环已经通了：一件东西从一张照片走到"对方拆开读到那句话、再回一句、再寄回去"，中间没有断点，也没有哪一步是示意。

## 四、技术方案

### 4.1 一件东西两次 Lux3D 任务

现在的真链路是两步，不是三次：

1. `imgTo3d.create({ imageUrl, faceCount: 200000, glb, enablePbr, aiPredictSize })` —— 照片出带材质的形状。
2. `partSplit.create({ glbUrl })` —— 按结构拆成独立零件，回一个拆分后的 GLB。

产物下载到 `public/items/gen<id>/`，再跑一次材质回压（metallic 0.12、roughness 0.5，拆出来的 GLB 默认偏亮，放雾白底上像塑料），数 GLB 节点写进 `meta.json`，任务号与 URL 写进 `pipeline.json`，页面上原样展示。

2026-11-17 实跑一件：job `jmwkpt3mu8o6hb`，7 块，15.5MB，两个任务号 `8235025` / `8235303`。首页那台台灯就是这次真实产物。

早期演示件走过一次文本生 3D + 拆分 + STL 导出（三次任务），那批数字保留在旧记录里，但**现在的寄件链路是两次任务**，报告按现状写。

### 4.2 为什么拆分产物这么好用

七个 mesh 各自独立，坐标已经烘焙到世界系。拆一块不需要重算矩阵：给每块一个方向向量，让它沿自身相对整体的径向飞出去即可。方向按高度分带（上部往上、贴地往两侧），避免七块挤成一团。

### 4.3 玩法：难度不在"拆"，在"顺序"

拆装本身没有难度，所以难度被放在两处：

- **脱开方向可见，能不能动不可见**。鼠标移到零件上、或开始拖时，从零件上画一支白箭，指向它脱开的方向。但被别的零件压着的件同样有箭头——箭头只说"它往哪边走"，不说"它现在能不能走"。要试。
- **顺序有代价**。拽错方向记一次撬痕；硬拉被压住的件也记一次。被压的件前两次只抖一下、闷响，**第三次才点名**"先拆灯罩"。撬痕会撕掉纸条：每道撬痕吃掉纸的一截，尾句连同纸边一起没了，拆完还可以"重新拆一次"。
- **拆完有答案**。纸条上多一行「最旧的一块：<零件名>」，摊开后的货架标签同样标出这一块。拆的过程因此不只是拆，是在读一个人和一件东西的相处时间。
- **拆完有账**。纸条底部一行结算：「拆了 7 块 · 硬拽 0 次 · 用了 9 秒」，并存进本机；同一件再拆一次会写「比上次快 12 秒」或「比上次少硬拽 1 次」。重拆因此有理由，不是重复劳动。

### 4.4 四档显示

- 墨色：整体压成印刷品单色。
- 原色：还原材质，让评委看清模型细节。
- 套色：七块各乘一个孔版油墨色，像丝网分色稿。
- 线框：退成接近白模，只留 30° 折角的结构线。阈值是算出来的——27 万面全画三角网就是一团噪点，只留折角才读成制图线。

四档切换真实复原贴图、粗糙度、金属度，切回墨色不留白模残留。

### 4.5 手势

MediaPipe HandLandmarker 本地跑，模型与 wasm 都在 `public/mediapipe`，画面不出本机。

- 捏合判定：食指指尖与拇指指尖距离对掌心尺度的比值，`<0.40` 抓住、`>0.56` 且明显张开手掌持续 300ms 才松手。
- 捏住之后每帧补抓：手先捏、再挪到零件上也能抓住，不必先松手重捏。
- 抓取吸附 110px：指尖在 640×480 里只有十几个像素，细杆、电源线靠点准是点不中的。
- 单手横扫转视角，抓着东西时禁用，避免挥手把零件甩掉。
- 双手拉开控制摊开程度。
- 真机验收：2026-11-18 两次真摄像头测试，状态轨迹出现「捏住了 → 抓住了，往外拉」，实测拉掉一块（已拆 1/7），抓着时转视角误触帧数为 0。

### 4.6 回信为什么不重新生成

回信只是换一句话和署名，模型一个字都不用动。`/api/reply` 把原包裹码里的物件 id、照片、收件人署名与新句子重组成新码，跳到新的装盒页。这一步不调 Lux3D，不消耗积分，收件人回一句的成本是零。

## 五、视觉决策

界面按 Aholo 官网的语言做：雾白冷灰渐变底、1px 细线、深色胶囊控件、电光蓝点缀。零件标注用细引线加箭头，署名处直接写「Aholo Viewer 渲染 · Lux3D 生成」——技术栈不写在报告里，写在打开页面的第一眼。

文字坚持去装饰：没有英文小标签，没有 01/02/03 编号，没有"探索更多"。替换的是能听懂的话："按住一块，往外拉"、"被压着的拆不动"。

首页不是介绍页，是一个已经寄到的包裹：进来就能拆。左下角一行"寄一件你自己的 · 拍一张照，它会被拆成零件寄出去"，是唯一的外链入口——它不抢戏，但一定看得见。

## 六、按评审维度自评

| 维度 | 权重 | 判断 |
|---|---|---|
| 群核技术栈 | 30% | 强。两次 Lux3D 任务都在真实链路里，拆分产物直接变成可交互的七个零件，Viewer 渲染接进页面，任务号在进度页可见可查。 |
| 有趣 | 25% | 好。拆件读信成立，撬痕会撕纸、顺序错了要重来，"最旧的一块"让拆解有了答案。 |
| 创新 | 20% | 中上。把"寄一句话"做成可拆解的物件，比常见情书生成器多一层动手成本；回信不烧额度，闭环可复制。 |
| 完成度 | 20% | 中上。六段全通、真机验过手势；扣分在没有公网部署链接、没有成片 Demo。 |
| 传播 | 5% | 弱。还没有对外发过。 |

## 七、已知限制（如实写）

1. **没有公网地址**。当前只能本地 `npm run dev -p 3100` 打开。评委点不进来，这是最大的实际损失，提交前必须解决或换成成片 Demo 承载。
2. **生成件没有零件名**。真实链路跑出来的件，`meta.parts` 为空，标签回落成"第 N 块"；只有演示件有"底座/灯杆/灯罩"这类名字。命名还没接进生成流程。
3. **只有两件真实产物**。一件文本生（台灯），一件图生（job `jmwkpt3mu8o6hb`）。要证明流程通用，还得跑椅子、收音机之类第二三件。
4. **手势刚达可用**。阈值与吸附为真机手调，不同光线、不同手掌大小仍会有偏差；已经不再追求"捏死"，而是把容错放在判定层。
5. **摊开时标签淡入偏晚**，货架摆位偶尔互压，属观感问题，不影响判定。

## 八、Demo 脚本（60–90 秒）

| 时间 | 画面 | 动作 |
|---|---|---|
| 0–6s | 首页静止 | 台灯占满屏。左上"一个陌生人 寄来一件东西"，右下"按住一块，往外拉" |
| 6–12s | 抬起一块 | 悬停出白箭，沿箭头拽出第一块，零件落台面，计数 1/7 |
| 12–22s | 连拆三块 | 形状开始可疑；被压的件抖一下闷响，提示"被旁边的件卡着" |
| 22–30s | 撬痕 | 故意拽错方向，纸条被撕掉一截，顶栏"撬痕 1" |
| 30–36s | 拆到核心 | 原照片跟着纸条浮出：一张白模台灯照 |
| 36–42s | 读完那句 | 纸条给原句与「最旧的一块」 |
| 42–50s | 摊开 | 七块落位、编号与名称引线出现，货架标签标出最旧那块 |
| 50–58s | 四档 | 墨色 → 原色 → 套色 → 线框，各停 1s，线框停 2s |
| 58–72s | 寄一件 | 进 `/send`：选照片、署名、写那句话、让它长出来 → `/job` 六步 → 装盒页复制链接 |
| 72–84s | 回信 | `/p` 拆到底 → 回一句 → 新装盒页出现 |
| 84–90s | 收尾 | 镜头绕半圈，字幕：「一件东西拆成零件，一句话藏在里面。」 |

录制要求：1440×900、无浏览器边框、无加载转圈、鼠标指针尽量不出现在画面里。

## 九、复现

```bash
npm install
npm run dev -- -p 3100
# 首页（可玩的包裹）：http://localhost:3100
# 寄件：http://localhost:3100/send      → 进度 /job/<id> → 装盒 /s/<码>
# 收件拆件：http://localhost:3100/p/<码>
# 回信：http://localhost:3100/r/<码>
```

验证脚本（`.tmp/`）：`note-shot.mjs` 纸条态、`flow-shot.mjs` 逐块拆完、`flow2-shot.mjs` 摊开标签、`arrow-shot.mjs` 方向箭、`hand-shot.mjs` 手势面板、`home-shot.mjs` 首页、`pages-shot.mjs` 各页截图、`camera-test.mjs` 真摄像头验证。

真实生成（消耗积分）：

```bash
node scripts/jobs/run.mjs --id <jobId>
```

凭据只存在 `.env.local`（`AHOLO_API_KEY` / `AHOLO_REGION`），不入库。
